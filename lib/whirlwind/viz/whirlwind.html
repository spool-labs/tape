What this shows

Whirlwind is a signal, not a consensus. Owners of one spool group repeatedly challenge one another to prove they still hold the bytes they were assigned. There is no leader and no cross-round chain: each round stands alone, and each node keeps its own local score.

Every round draws one byte-weighted, fixed-size sub-leaf of each spool's stored data, enumerated by track number. A large track spans many leaves, so inspection follows stored bytes, not object count. The challenged owner reads that leaf and broadcasts a signed Merkle proof of access.

Two clocks. The response deadline runs from block production — the seed is visible the moment the entropy block is produced, well before finality. Signing opens on confirmation, once a supermajority has voted for that block. A peer signs only if it received a valid proof before the deadline; at 14 matching signatures anyone aggregates a BLS success certificate for that one spool. A challenged spool may self-attest for liveness but cannot self-certify.

A void round counts against nobody: if no block in the round's span reaches finalized history, there is no entropy, so the round is discarded. No certificate is a local miss, never a proof of failure; a late certificate can turn a miss back into a success.

Why fourteen. Any two 14-signature quorums out of 20 intersect in at least 8 owners, and with at most 6 Byzantine that intersection holds at least 2 honest. So conflicting certificates cannot both stand — 14 forces honest overlap.
Honest data note. City-to-city pings and per-box sha256 / bls / clay compute are real measurements. Disk is deliberately not modeled, because on the target hardware the proof path is network-bound. Blockhashes, keys, and signatures are illustrative. Rounds sit 150 slots apart (60 s) and each one is over in a few seconds, so playback skips the idle gap between them. Block production is set to 0.78 per slot rather than mainnet's ~0.95 so that a void round appears in a run short enough to watch. The relay and deadline controls rebuild the run on the same seed, so whatever moves is the knob and not a different draw. At every schedulable deadline, meaning any whole number of 400 ms slots, the nearby-fetch free-rider, the reconstruct free-rider and the selective spool all certify and survive, and only a spool that answers nobody or can never produce a valid proof is caught. The 200 ms setting is a counterfactual: it is offered to show that the reconstruct free-rider is separable in principle, but the slot clock has no way to express a deadline inside a slot, so the network cannot run it. Under direct relay the selective spool is caught, and a single hop of forwarding is enough to carry its proof to the peers it skipped and save it. The faults control injects weather, which a local rule cannot tell apart from a spool that is gone. Over 150 seeds it shows the trade the deadline really makes: at 2 slots almost no honest node is ever evicted by weather but no free-rider is caught, while at 200 ms the reconstruct free-rider is caught every time and a sustained regional degradation evicts an honest node in 60% of runs. The tight deadline is not merely unschedulable, it is unsafe. Fault rates here are a chosen scenario, not a measurement.
